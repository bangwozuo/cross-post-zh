## 能力描述

把内容池排成跨平台发布日历并给出时段建议。每步量化验收：

1. **S1 条目解析**：每条解析出平台与《标题》，禁排日全部剔除
2. **S2 发布日历生成**：同平台每天至多 1 篇；同日晚间跨平台按 ≥1 小时错峰；「必须」条目撞车不硬塞
3. **S3 时段建议**：午间 12:00-13:00 / 晚间 20:00-22:00 两档，建议 2-5 条
4. **S4 人工确认**：确认前不执行任何发布动作

## 使用步骤

### 方式一：纯提示词编排（跨平台）

1. 把 `prompt.txt` 全文粘贴为系统提示词
2. 提供内容池与约束条件
3. 按 S1→S2→S3→S4 顺序执行，得到排期表与时段建议

### 方式二：带脚本（端到端产物）

```bash
python <WF_DIR>/scripts/run_flow.py --demo
python <WF_DIR>/scripts/run_flow.py --input examples/input.json --outdir out
```

脚本逐节点解析条目、按优先级排期（平台日名额 + 晚间错峰 ≥1 小时），
产物落 `out/发布排期表.md` 与 `out/flow_result.json`。名额与冲突判定以脚本输出为准。

### 方式三：平台编排

| 平台 | 编排方式 |
|------|---------|
| **Coze / 扣子** | 新建工作流 → 按步骤添加节点，每个节点填入对应技能的 prompt.txt |
| **Dify** | 新建 Workflow → 添加 LLM 节点链，按 DAG 顺序连接 |
| **WorkBuddy** | 新建 Skill，按步骤在指令中串联各技能提示词 |

## 边界（不做的事）

- ❌ 不自动执行任何发布动作——只到排期表为止
- ❌ 不硬塞排期——排不下如实列「未能排入」，不静默顺延
- ❌ 不编造平台流量数据——时段建议只给经验档位，不给虚构数字
- ❌ 不处理「必须日」撞车的自作主张改期——转人工确认
- ❌ 无平台写权限——不申请、不调用任何发布接口

## 调用示例

**输入**（`examples/input.json`）：内容池 4 条（小红书×2、抖音、公众号）+ 约束
（工作日 12:00-13:00 / 20:00-22:00、小红书每天 1 篇、10月12日不可用）。

**输出**（脚本实跑）：4/4 排入；10月13日晚间两条跨平台条目按 20:30/21:30 错峰；
排期表落 `out/发布排期表.md`。
