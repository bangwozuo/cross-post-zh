> 复合技能 = 工作流。它把多个**原子技能**按业务顺序编排在一起，完成一个完整场景。

## 能力描述

把「应发清单 × 实发记录」逐条核对并产出漏发提醒。每步量化验收：

1. **S1 清单解析**：应发条目须解析出平台 + 《标题》 + 计划时间三要素，实发记录允许为空
2. **S2 逐条核对**：偏差 ≤30 分钟同日为准时，同日超窗为迟发，无记录或跨日为漏发
3. **S3 漏发提醒**：每条含条目标识 + 计划时间 + 原因 + 1 条可执行建议
4. **S4 人工处理**：不自动补发，动作回流排期工作流

## 使用步骤

### 方式一：纯提示词编排（跨平台）

1. 把 `prompt.txt` 全文粘贴为系统提示词
2. 提供应发清单与实发记录（平台后台导出，只读）
3. 按 S1→S2→S3→S4 顺序执行，得到核对表与漏发提醒

### 方式二：带脚本（端到端产物）

```bash
python <WF_DIR>/scripts/run_flow.py --demo
python <WF_DIR>/scripts/run_flow.py --input examples/input.json --outdir out
```

脚本正则解析两份清单、按「标题+平台」精确匹配核对（±30 分钟窗口），
产物落 `out/发布状态核对.md` 与 `out/flow_result.json`。状态判定以脚本输出为准。

### 方式三：平台编排

| 平台 | 编排方式 |
|------|---------|
| **Coze / 扣子** | 新建工作流 → 按步骤添加节点，每个节点填入对应技能的 prompt.txt |
| **Dify** | 新建 Workflow → 添加 LLM 节点链，按 DAG 顺序连接 |
| **WorkBuddy** | 新建 Skill，按步骤在指令中串联各技能提示词 |

## 边界（不做的事）

- ❌ 不自动执行任何补发——补发由人工确认后执行
- ❌ 不猜测发布状态——记录缺失一律按漏发列出并注明「未查到记录」
- ❌ 不做模糊标题匹配——标题+平台须完全一致
- ❌ 不使用平台写权限——实发数据只读，来自用户导出记录
- ❌ 不编造发布数据与流量数据

## 调用示例

**输入**（`examples/input.json`）：应发 4 条（小红书×2、抖音、公众号，10月12-13日）+
实发记录 2 条。

**输出**（脚本实跑）：准时 2 条（偏差 1 分钟 / 0 分钟）、漏发 2 条，
漏发提醒含晚间 20:00-22:00 补发档位建议；核对表落 `out/发布状态核对.md`。
