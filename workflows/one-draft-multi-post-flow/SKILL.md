## 能力描述

把一篇原稿端到端产出抖音口播、小红书笔记、B站简介三个平台版本。每步量化验收：

1. **S1 平台风格改写**：抖音 200-260 字（60 秒）、小红书 300-800 字、B站 ≤300 字；原稿数字 100% 保留
2. **S2 小红书笔记排版**：Emoji 全文 ≤7 个、文末标签 3-6 个、条目行 3-6 行
3. **S3 口语化改写**：单句 ≤25 字、改动说明 ≥2 条、字数偏差 ±10% 内
4. **S4 人工对稿**：数字核对不过即退回对应步骤

## 编排的原子技能

| # | 原子技能 | 能力 |
|---|---------|------|
| 1 | [平台风格改写](../../skills/platform-style-rewrite/) | 同一内容按平台语境重写 |
| 2 | [小红书笔记排版](../../skills/xhs-note-layout/) | Emoji/分段/话题标签的小红书格式化 |
| 3 | [口语化改写](../../skills/colloquial-rewrite/) | 书面腔转口语，单句 ≤25 字、字数偏差 ±10% 内 |

## 使用步骤

### 方式一：纯提示词编排（跨平台）

1. 把 `prompt.txt` 全文粘贴为系统提示词
2. 提供原稿与目标平台清单
3. 按 S1→S2→S3→S4 顺序执行，每步按量化验收判定通过/打回

### 方式二：带脚本（端到端产物）

```bash
python <WF_DIR>/scripts/run_flow.py --demo
python <WF_DIR>/scripts/run_flow.py --input examples/input.json --outdir out
```

脚本按 DAG 逐节点执行并实测字数/Emoji/标签数，产物落
`out/一稿多投交付.md` 与 `out/flow_result.json`。数值一律以脚本输出为准。

### 方式三：平台编排

| 平台 | 编排方式 |
|------|---------|
| **Coze / 扣子** | 新建工作流 → 按步骤添加节点，每个节点填入对应技能的 prompt.txt |
| **Dify** | 新建 Workflow → 添加 LLM 节点链，按 DAG 顺序连接 |
| **WorkBuddy** | 新建 Skill，按步骤在指令中串联各技能提示词 |

## 边界（不做的事）

- ❌ 不产出抖音/小红书/B站之外的平台版本（公众号图文需另配排版技能）
- ❌ 不悄悄增删事实——原稿数字对不上即打回，不静默改数
- ❌ 不跳过 S4 人工对稿直接宣称交付
- ❌ 不用模型口算字数——以脚本实测为准
- ❌ 不发布——只到终稿为止，发布动作由人工执行

## 调用示例

**输入**（`examples/input.json`）：公众号风格原稿（5 款保温杯四维度实测）+
目标「抖音口播、小红书笔记、B站简介」。

**输出**（脚本实跑）：三平台版本 + 排版核查（Emoji 5 个、标签 5 个）+
拆句建议；交付全文落 `out/一稿多投交付.md`。
